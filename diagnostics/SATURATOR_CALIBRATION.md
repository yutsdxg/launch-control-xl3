# Saturatorのバイパス基準によるDrive／Output補正

2026-10-30、Live 12.4.15で測定した。Issue #34で、音量の基準をDrive 0の処理音から実際にSaturatorをOFFにした原音へ変更した。対象は新Mixingの`parameter: "Drive"`に一致する割り当てで、デバイス名・操作子番号・Outputの操作子番号では固定しない。[本体の仕様](../Launch_Control_XL_3_Mixing/SPEC.md#saturatorのdriveに連動するoutput補正)と[測定数値・音声SHA-256](saturator_measurements.json)を参照する。

2026-10-31のIssue #36で実行時のColor OFF制限を外した。Color ONでも同じ補正表と手動トリムを使い、Colorの切替で休止・再基準化しない。ユーザー指定によりColor ON向けの追加較正はしていない。以下の測定条件・数値は引き続きColor OFFで測った結果である。

## 測定条件と基準音

- Analog Clip、Color OFF、Post Clip No Clip、Dry/Wet 100%、Hi-Quality ON、Pre-DC Filter OFF。
- 44.1 kHz、ステレオ32-bit float WAV。Warp・Fade・Normalize・DitherをOFFにし、Saturatorの後段にエフェクトを置かない。測定時のTrack／Mainは0 dB。
- FFmpegの`anoisesrc=color=pink:sample_rate=44100:duration=10:seed=32`で生成した同じノイズを、全10秒のRMSが−18 dBFSになるよう正規化した。左右は同一信号、ピークは−3.494 dBFS。
- 各条件で同じ10秒を処理し、先頭・末尾0.5秒を除いた同じ9秒のRMSを比較する。全ファイルのRMSを測定窓の基準値として使わない。
- ノイズ・ベース・コード・ドラムを各12秒の区間へ置いた48秒のSetで、全SaturatorをOFFにして実際に書き出した。ノイズのOFF基準RMSは−17.981263835 dBFS。

旧測定のDrive 0処理音は−17.990446964 dBFSで、OFF基準より0.009183129 dB小さい。補正量は`OFFのRMS − 各Driveの未補正RMS`で求める。Drive 0で必要な微小な正補正はOutputの上限0 dBで制限し、標準トリムでのOutputを0 dBとする。

点の間はdBで線形補間する。測定点と中間点のノイズ17条件、および合成ベース・コード・ドラム各9条件の計44条件へ、新しいOutput補正量を実際に設定した。0〜528秒のMainを書き出し、各素材の実測OFF音量と比較した。旧レンダリングから新しい音声の結果を推定してはいない。

## 本体のDrive操作範囲を設定する

`mixing_config.py`のDrive割り当てへ`"min": 0.5`を加えると、エンコーダー／フェーダーの操作下限を0 dB、上限を36 dBにできる。フェーダーは全移動範囲を0〜36 dBへ再配分する。現行の個人配置ではDriveの行だけへこの指定を加え、ほかの配置は維持する。Live画面やオートメーションのパラメータ範囲は変わらない。

Issue #38では同じ正規化単位の`max`も指定できるようにした。省略時は`min=0`／`max=1`で、`0 <= min < max <= 1`とする。例えば`"min": 0.5, "max": 5 / 6`ならDriveを0〜24 dBで操作できる。上限の具体値は今回指定されていないため、個人のDrive設定は`min: 0.5`のままとする。

`min > 0`または`max < 1`の操作子だけ範囲専用の制御を使い、フェーダーの既定takeoverはスクリプト側の`value_scaling`となる。`pickup`・`none`も指定でき、Liveのグローバル設定へは自動追従しない。全範囲の`min=0`／`max=1`は従来のLive標準接続を使う。詳細な入力・復帰仕様は本体の仕様を参照する。

この設定は補正表を拡張しない。0〜24 dBの補正と測定値は従来のままで、24〜36 dBでは24 dBの補正量を維持する。`auto_bypass`の最小端点は設定下限の0 dBとなり、端点のOutput補正を反映してからデバイスをOFFにする。

## 保存値と手動トリム

標準トリムは0 dB。保存済みOutputやロード時の復元通知をトリムへ継承せず、最初にDriveが実際に変わった本体入力でバイパス基準へ合わせる。起動・選択・Pickup待ちだけではOutputを書かない。

マウスDrive変更はOutputや基準を変更しない。次の有効な本体Drive操作から補正へ戻る。基準化後の手動Output変更、および実値が変わった本体Output操作は明示トリムとして保持する。同じデバイスの明示トリムはセッション中のトラック・モード切替やShift・条件休止をまたいで保持し、スクリプト終了時には消す。手動トリムを下げた場合、OFF時にはその減衰が適用されないため、その操作分の音量差は残る。

## 実機の通知順と確認用Set

[読み取り専用の診断Surface](LCXL3_Saturator_Probe/README.md)で、Live 12.4.15の「native実値更新→物理入力callback→Drive変更通知」を確認した。Pickup待ちの75入力ではDriveは変わらず、76入力目で追従した。内部値は0〜1で、Driveは`72v − 36` dB、Outputは`36v − 36` dBへ換算する。他のLiveバージョンで挙動が変われば再診断する。

Issue #32の旧確認用Setは、CodexがSaturator Outputへ−12 dBを設定していた。旧処理はそれを維持したため、OFFにすると12 dB大きくなった。旧実機記録はJSONの履歴項目に保存し、現在の標準基準として扱わない。

Issue #34の確認用SetはDrive 0 dB／Output 0 dB、後段のトラック音量−12 dBとした。入力素材のRMSを変えず、ON／OFF両方へ同じ減衰をかける。補正本体の動作に診断Surfaceは不要である。

修正版をLiveへ反映して再起動した後、ユーザーがこのSetでON／OFF比較を行い、「急に大きくなる現象はなくなった」と確認した。実測したRMS差とは別に、問題として報告されたバイパス時の急な音量増加が解消した実機確認として記録する。

Issue #36では最新版をLiveパッケージへ反映して再起動し、元のSetを保存したコピー`LCXL3_issue36_session`でColor ONのまま確認した。ユーザーへ本体Driveフェーダーの下端→上端→下端の操作を依頼し、Driveが0〜36 dBに収まること、Outputが連動すること、下端でデバイスOFF・上げるとONへ戻ることの3点について、2026-10-31に「OKです」と回答を得た。これは動作確認であり、Color ONの音響再較正やPRの最終承認とは別である。
