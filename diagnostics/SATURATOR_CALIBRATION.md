# SaturatorのDrive／Output補正の測定記録

2026-10-30、Live 12.4.15で測定した。補正は新Mixingの`parameter: "Drive"`への割り当てに自動適用する。デバイス名・操作子番号・Outputの操作子番号では対象を固定しない。詳しい動作は[本体の仕様](../Launch_Control_XL_3_Mixing/SPEC.md#saturatorのdriveに連動するoutput補正)、数値と音声のSHA-256は[saturator_measurements.json](saturator_measurements.json)を参照する。

## 測定条件

- Analog Clip、Color OFF、Post Clip No Clip、Dry/Wet 100%、Hi-Quality ON、Pre-DC Filter OFF。
- 44.1 kHz、ステレオの32-bit float WAV。Warp・Fade・Normalize・DitherをOFFにし、Saturatorの後段にエフェクトを置かない。
- FFmpegの`anoisesrc=color=pink:sample_rate=44100:duration=10:seed=32`から生成した同一のピンクノイズを、RMS −18 dBFSへ正規化して使用。左右は同一信号、ピークは−3.494 dBFS。
- 各条件で同じ10秒を処理し、先頭・末尾0.5秒を除いた9秒のRMSを比較する。基準区間のRMSは−17.990447 dBFS。
- 測定用Setでは各条件を12秒間隔で配置し、Mainを0〜204秒、32-bit float、Normalize OFFで一括書き出しした。

## 補正表

Outputを0 dBへ固定して、Drive 0／3／…／24 dBの出力を実測した。補正量は同モードのDrive 0 dB時との差で求め、dBで線形補間する。

| Drive（dB） | Output補正量（dB） |
| ---: | ---: |
| 0 | 0.000 |
| 3 | −3.000 |
| 6 | −5.995 |
| 9 | −8.907 |
| 12 | −11.481 |
| 15 | −13.489 |
| 18 | −14.919 |
| 21 | −15.885 |
| 24 | −16.517 |

次に、各測定点と中間点の計17点について、実測表の補正量を実際のSaturatorのOutputへ設定し、再び音声を書き出した。Drive 0 dB時からのRMS誤差の最大値は**0.076255 dB**。0〜24 dBにおける基準信号の目標±0.5 dBを満たした。これは固定値の音声レンダリングによる検証であり、操作中の瞬間的な段差の評価とは区別する。

## 別素材での残差

決定的に生成した10秒の合成ベース・コード・ドラムを、それぞれRMS −18 dBFSへ正規化した。各素材でDrive 0／3／…／24 dBと同じ共通補正表を使い、補正後の実音声を0〜324秒のMain書き出しで測定した。以下は各素材のDrive 0 dB時を基準にしたRMS差であり、実楽曲全般の保証ではない。

| 素材 | 最小差（dB） | 最大差（dB） | 最大絶対差（dB） |
| --- | ---: | ---: | ---: |
| 合成ベース | 0.000 | ＋0.495 | 0.495 |
| 合成コード | −0.180 | ＋0.008 | 0.180 |
| 合成ドラム | −2.459 | 0.000 | 2.459 |

特にドラムのようにピークの高い素材では、Driveを上げるほど補正が強すぎて小さくなる場合がある。入力レベルや波形が異なれば必要な補正の形も変わるため、手動Outputは残す。Drive全域で残差が変わる場合は、一定のOutput調整だけでは完全には揃わない。今回は共有カーブを使う初版として、この残差を記録する。

## 実機の入力通知と内部値

[診断用Surface](LCXL3_Saturator_Probe/README.md)をMIDI入出力Noneで追加し、既存のネイティブマッピングを変更せずに確認した。

- 最初のフェーダー往復で254件の操作入力と252件のDrive変更通知を記録した。入力callbackの時点で実値は更新済みで、Drive変更通知はその後に届いた。
- マウスでDriveを0 dBへ設定した後、Pickup待ちの75件の有効入力ではDriveは0 dBのまま、76件目で追従を開始した。Value ScalingでもCC値から逆算せず、実際に受け入れられたDrive値を読めることを確認した。
- Drive／Outputの内部値は0〜1。Driveは`72v − 36` dB、Outputは`36v − 36` dBへ換算する。Drive ＋12 dBは0.666667、Output −6 dBは0.833333であることを実機で確認した。
- この通知順はLive 12.4.15での観測に基づく。他のLiveバージョンで挙動が変わった場合は、この診断から再確認する。

補正は物理入力を扱う間だけOutputへ書き込む。独立したDrive変更通知は基準の更新だけを行う。同じDriveへの複数割り当ては状態を共有し、自動Output通知と手動変更を区別する。休止・復帰・Output上下限の扱いは本体の仕様に記載した。

## 実装配置後の操作確認

補正本体をLiveへ配置して再起動した後、6番目にSaturatorを置いた専用の検証Setを使い、現行配置のDriveフェーダーとOutputノブを操作した。ユーザーから連動を確認したとの回答を得た。MIDI Takeoverは検証前のValue Scalingへ戻した。

1,176件の有効な操作入力を記録し、実際のDriveは−36〜36 dB、Outputは−28.232〜−11.715 dBの範囲で変化した。`Output_dB − C(Drive_dB)`は最初の17入力で約−12 dB、手動Output調整後の1,159入力で約−11.7148 dBを維持した。これは実機上での補正関係と手動トリムの保持の確認であり、音声RMSの誤差とは別の指標である。

ユーザーによる聴感確認では、速いDrive操作で気になる段差はなかったとの回答を得た。今回の検証用合成ベースでの主観的な確認結果として記録する。

検証後、追加した診断Surfaceの行をNoneへ戻し、本体のControl Surfaceと入出力は維持した。本体の補正機能は診断Surfaceを必要としない。
